# RG280V単体FCEUXの速度低下調査（2026-11-16）

## 条件

- 実機: RG280V、CPU 996 MHz、governor `userspace`。
- ROM: SD2の `Akumajou Densetsu.nes`。単体FCEUX 2.6.6を通常のplumOS起動ラッパーから起動した。
- ROM別設定は `SDL.Sound.Rate=48000`、`SDL.Sound.Quality=1`、`SDL.Frameskip=0`、`SDL.FPSThrottle=0`。通常の音声が正常と確認されていた設定を基準にした。
- `SDL_Flip` をLD_PRELOADで計時し、2秒ごとの回数と実行時間を記録した。初回2秒は起動直後として平均から除外。各試験は12秒で終了した。

| 条件 | 画面更新/秒（安定区間平均） | `SDL_Flip`平均 | 読み取り |
| --- | ---: | ---: | --- |
| 基準: 48 kHz、描画スキップ0 | 約53.5（後半3区間は54.1） | 約0.59 ms | 60 FPSに届かない |
| 音声OFF、描画スキップ0 | 約106.5 | 約1.46 ms | 映像経路単独なら60 FPSを超える |
| 32 kHz、音質1、描画スキップ0 | 約59.7 | 約0.54 ms | ほぼ60 FPS |
| 48 kHz、描画スキップ6/12 | 約30.1 | 約0.49 ms | 内部進行は約60 FPS相当 |

基準の安定区間は51.78、53.95、54.11、54.24 FPS。後半3区間平均が54.1 FPS。32 kHzは59.66、60.16、60.04、58.95 FPS。スキップ6は12フレーム中6フレームを省くため、約30回の画面更新は約60フレームの内部進行に相当する。

5.084秒間の基準動作でFCEUXは505 CPU tickを使用し、ほぼ1コア全体を使っていた。主スレッドにCPU使用が集中し、音声スレッドの使用量は小さかった。`SDL_Flip`は1回あたり約0.5～0.6 msなので、表示転送待ちが直接54 FPSへ制限しているわけではない。音声OFFと32 kHzで大きく改善することから、**48 kHz音声を伴う主ループの処理量が支配的**。音声生成と音声バッファへの書き込みのどちらに何ms掛かるかは、この計測では分離できない。

試験後、ROM別設定のSHA-256が元の `29c8081d6985a35b0b24f969e12f7eb506b4f9276ad7c3526952f14108edb20b` に戻ったことを確認し、FEプロセスも再起動して確認した。その後、実機での音の確認用としてこのROMだけ32 kHzへ再設定した。全ROMの設定は変更していない。32 kHzでの音質と操作感はユーザーの物理確認待ち。

計測コード: `scripts/rg280v-fceux-flip-probe.c`、`scripts/build-rg280v-fceux-flip-probe.sh`、`scripts/measure-rg280v-fceux.py`。ROMと試験設定のバックアップ、画面画像、端末側のTSVは `output/validation/rg280v-fceux-performance-20261116/` とSD1の `Logs/` に置き、Gitには含めない。
