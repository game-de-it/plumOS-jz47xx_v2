# RG280V GCW Zero OPK apps (2026-11-16)

## Integration

The RG280V rootfs already provides `opkrun` and `opkinfo`, and SD1 has `/media/data/apps`. START now contains Apps. Opening Apps scans regular `.opk` files in that directory, reads the first `Name:` from `opkinfo`, and displays the names in sorted order. The scanner limits names and filenames, excludes symlinks, and leaves the other plumOS devices unchanged. The existing FE shell-app path releases the renderer while the app runs and reinitializes it afterward. The new `plumos-opk-app-launch` prepares the GPIO input metadata, writable HOME, SDL KMSDRM and auxiliary library path before calling `opkrun`. OPK transfer now uses a temporary destination and SHA-256 comparison before rename.

START's six entries fit in the 320x240 logical display with 24-pixel row spacing. The live 320x480 DRM capture shows the model and charging status still present. The Apps list is populated when opened, so adding or removing an OPK does not require a FE rebuild.

The input tester appeared in Apps by its OPK metadata. It opened at 320x240; injected D-pad and ABXY events were consumed and changed the display. The user pressed physical SELECT and START+SELECT and confirmed return to FE. An additional injected START+SELECT exit also returned to Apps; B navigated to TOP. The FE process remained running. Its installed binary matches local SHA-256 `41a0c61039e96d4d2849ceebccdba93f3ecb21452d7cf7fece31ad32b705f419`. Temporary key injection and unsuccessful trial OPKs were removed from the device. Captures are in ignored `output/rg280v-apps/`.

`scripts/build-rg280v-input-test-opk.sh` pins the upstream revision and exports the modified GPL source including the no-rumble stub. Two builds produced identical OPK and source archive hashes. The installed source archive SHA-256 is `59ed8ea1cace596e5bf37fea87fd923f1d4bc8db12e20ff25f46642f3ab24874`. The image build recipe installs the OPK and source archive on future builds. No SD image was generated in this change. Other OPKs still need individual ABI, library, display and input checks before they can be called compatible.
