# RG280V PyMenu integration — 2026-11-19

## Implementation

- Original JackD83/PyMenu source: `68ceb9d17c4016d68abd6cd7c382eea5cbfd2009`.
- Original Pygame 1.9.6: `34f25f42f7c44774460eb8cbc8de19c1903e1e66`; private Python 3.11.6 runtime, built with the existing MIPS/uClibc toolchain.
- Original Pixel/Default artwork and UI retained. Python 2 dictionary comparisons changed to filename sorting, the scandir backport replaced by `os.scandir`, and Pygame's legacy float-to-pixel conversion restored in the private extension.
- 26 enabled formal systems, 58 registered emulator routes; default route listed first, alternatives labelled `SA:core` / `PICO:core`. Existing formal launchers retain ROM, BIOS, emulator settings and return handling.
- ROMs remain on SD2; Python/UI/config live on SD1. No boot/kernel/global SDL/ALSA change. Power, sleep, brightness, volume and CPU remain under plumOS control.
- Writable configuration: `/media/data/plumos/home/pymenu/config`. Resume state is namespaced in `/tmp` and cleared on a fresh Apps entry; preserved only when returning from a child game.
- FE Japanese font and its licenses reused. Stock artwork retained for known machines; other names receive the corresponding existing plumOS logo.

## Device evidence

- Original main carousel and NES ROM list captured from the active DRM plane.
- A enters NES; arrows move the ROM selection; START opens the emulator chooser with all five NES routes, B dismisses it.
- A launches SD2 `Akumajou Densetsu` through formal SA FCEUX. SELECT+START opens the emulator menu. UP to Exit, A exits; PyMenu resumes the same ROM list without nesting another frontend supervisor.
- Final private runtime was also tested with `Baseball.nes` using PICO FCEUmm, including its SELECT+START menu and normal Exit back to PyMenu.
- B returns to the main carousel; DOWN selects its power icon; A opens `Return to plumOS`; A exits normally.
- Apps registration and launch were exercised through the native plumOS FE. Normal return re-exposes the existing FE process.
- Screenshots/logs remain under ignored `output/rg280v-pymenu/`. Audio quality and all 58 emulator routes were not re-audited; they reuse the already accepted formal routes. Physical operation remains available for user review.

## Reproduction

1. `scripts/build-rg280v-pymenu.sh` builds the private runtime and applies both checked-in patches. It restores the prior Buildroot `.config` afterward and does not build an SD image.
2. With PyMenu stopped, `python3 scripts/install-rg280v-pymenu.py --register` checks available SD1 space, transfers and verifies the installation archive, backs up Apps config, and registers PyMenu. Existing writable user config survives reinstall.
3. Apps → PyMenu. In ROM lists START selects the emulator; A launches; B returns. Main carousel → DOWN → power icon → A → `Return to plumOS` → A returns to the native frontend.
