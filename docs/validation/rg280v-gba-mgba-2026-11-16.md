# RG280V GBA mGBAの30 FPS（2026-11-16）

ユーザーがFE登録順のGBA候補を確認し、mGBAのみ約30 FPSと報告。PicoArchログからgpSPとmGBAがSD2の`Densetsu no Stafy 3 (Japan).gba`を起動・終了したことを確認した。ReGBAとgpSPはユーザーの報告では正常だが、今回の個別FPS数値は取得していない。

mGBAの`mgba_frameskip`は上流既定で0、端末の個別設定ディレクトリにも上書きはない。同じROMの20秒診断で最後の映像更新窓は29.99 FPS、`SDL_Flip`待ちは平均12.176 ms/回。約33.34 ms/フレームから画面待ちを引くと約21.16 msで、60 Hz表示の16.7 ms枠を超える。描画だけの省略ではなく、処理量と同期による30 FPS固定と整合する。

`Idle Loop Removal`を`Remove Known`から`Detect and Remove`へ変えた比較ビルドも最後の窓は29.99 FPS。改善がないので試験版を撤回し、端末とローカル出力のmGBAコアを旧SHA-256 `337047e3a09d9cbd314483eec28ce771c78b54efe4d9e0ea5e7714cb4bf1baa5`へ戻した。比較用SHA-256は`7308d35b9f242aa1127edff1f9913ac944fec652ac3959ef49ea23f9f427d68d`。計測JSONはGit管理外の`output/rg280v-emulators/mgba-stafy3-20261116/`と`output/rg280v-emulators/mgba-stafy3-idle-detect-20261116/`に保存。

60 FPSを満たさないためmGBAをGBAのFE候補から外す。コア本体とビルドレシピは調査用に保持し、FEの候補は単体ReGBA、PicoArch gpSPとする。

FE設定のSHA-256は`610cbf5dac4022cdb9b02b5416f2359898fa7846b3085a4bec4a198bc3f43373`。端末への配置後に読み戻したJSONがリポジトリと一致し、現在のGBA選択は単体ReGBA。FE再起動後のプロセス稼働と旧mGBAコアのハッシュ復元を確認した。
