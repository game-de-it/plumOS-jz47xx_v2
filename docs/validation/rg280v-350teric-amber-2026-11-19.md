# RG280V 350teric: Amber skin

Implemented the approved black/charcoal/orange instrument-style design. The
approved image is retained at `docs/design/rg280v-350teric-amber-concept.png`.
Implementation uses native 320×240 rendering, not a background picture containing
menu entries or pre-rendered cursor states.

## Assets and installation

- Original project skin: `assets/rg280v-350teric/skins/Amber`.
- Deterministic frame, input symbols and device line art generator:
  `scripts/build-rg280v-350teric-amber-assets.py` (Pillow).
- Build the matching frontend with `scripts/build-rg280v-350teric.sh`.
- After exiting 350teric, install/update with
  `python3 scripts/install-rg280v-350teric-amber.py`.
- Standard `install-rg280v-350teric.py` also includes project-owned skins on new
  installations and adds missing ones without replacing existing user skin edits.

The Amber installer checks the connected device, 10 MiB free SD1 space, transfer
SHA256 and the deployed executable SHA256. It backs up the previous executable,
active config and any previous Amber directory under
`/media/data/plumos/backup/350teric-amber-*`. It preserves the current skin
selection; activation was then tested using START → Skin → Amber → START.
Default, Minimal and all four external skins remain installed. SD2 ROMs, BIOS,
save files, kernel, startup frontend and emulator profiles are unchanged.

Final deployed binary SHA256:
`83718a72ede605fafaa6171ec04aa61df870068c0b2cee58da19861dfd068df4`.

## Design and renderer

Palette: background `#080A0B`, selection/panel `#141719`, text `#B8BCBE`, muted
frame `#505558`, accent `#F28C28`. Body/title size is 14, status/footer size 11;
settings use 12-pixel body text to keep the native two-column editors readable.
The common full-CJK font is inherited. No game art or third-party skin imagery is
used in Amber's frame or device icons.

The optional `instrumentStyle=1` skin extension, used with one list column,
provides the shared inset frame geometry, six rows, thin selection rule, orange
selected text, top category/clock/charging status and restrained footer hints.
`accent` is an RGBA skin setting. Both fields survive skin-settings saves.
Existing skins default to `instrumentStyle=0` and keep the legacy renderer.

Device symbols have normal and selected colors and are shared by machine type,
not generated separately for every menu entry. Themed icon lookup and fitted
surfaces are cached. Titles, filenames and selection positions remain live data
from the existing 350teric menu and selector. Category navigation, link editing,
favorites and existing game launch routes retain native input handling.

The ROM selector uses the same header and six-row selection style; previews are
OFF by default. Footer text describes the actual native controls: A plays, B goes
up a directory, X adds a favorite, START returns to the launcher. Settings suppress
the old per-setting button-strip painting to prevent overlapping the new footer;
boolean indicators use orange/gray instead of green/red.

## Supporting fixes

- This RG280V kernel exposes battery voltage, not `capacity`. The power backend
  now uses the same voltage/min/max conversion and 0–100 clamp as the plumOS FE,
  with `usb-charger/online` determining CHG. The connected device showed CHG 100,
  consistent with the FE. Missing readings are represented as unknown, not a fake
  percentage.
- Upstream clock formatting could read an uninitialized cached `tm` after a game
  returned directly into a restored selector, producing 00:00. Clock formatting
  now refreshes its source first.
- A scoped two-second status pulse updates an Amber ROM selector even when it is
  entered before the main renderer's timer is constructed. Its callback only
  posts the native NOOP event; input and painting stay on the UI thread. The timer
  is removed when the selector closes. NOOP handling clears stale action flags so
  status redraws cannot replay a previous button press.

## Device verification

Using the RG280V's active DRM framebuffer and injected physical input events:

1. Activated Amber through the native START settings and captured the six-row
   emulator list, orange cursor/text/icon and full device outlines.
2. Opened settings, moved the selection, and checked label/value visibility,
   orange/gray booleans and the footer without overlapping controls.
3. Switched to legacy Default and captured its original layout, then switched
   back to Amber. The source flag is opt-in, not a global skin replacement.
4. Opened the NES ROM list, navigated to its last entries and captured readable
   Japanese names including 忍者龍剣伝 and 星のカービィ 夢の泉の物語.
5. Compared the ROM body crop before/after five idle seconds: byte-identical
   selection/body across periodic status redraws, with no phantom cursor moves.
6. Launched standalone FCEUX with 魔界村.nes, opened SELECT+START, exited and
   returned to the same ROM selection. Repeated after the final clock/input fix;
   the return screenshot showed the correct current time rather than 00:00.
7. Opened SELECT's native edit menu and canceled it without modifying any link.
8. Used Settings → Return to plumOS, confirmed the Apps page and process exit,
   then relaunched 350teric through Apps. `skin="Amber"` persisted.

The main list, settings and Japanese ROM capture each had zero pixels with
strong chroma outside the orange direction (`max(R,G,B)-min(R,G,B)>40` and not
`R>=G>=B`). This is a palette regression check, not an audio/FPS benchmark.
No OS reboot or physical unplugged-battery test was performed for this skin task.

Evidence under ignored `output/rg280v-350teric/`:
`amber-main.png`, `amber-settings.png`, `amber-roms.png`, `amber-japanese.png`,
`amber-legacy-default.png`, `amber-idle-before.png`, `amber-idle-after.png`,
`amber-final-game-menu.png`, `amber-final-game-return.png`, `amber-edit-menu.png`,
`amber-fe-return.png`, `amber-final.png`, `build-amber.log`, `install-amber.log`.

The device is left in Amber's emulator list. Change skins using START → Skin,
Left/Right and START to save. The design is intended for this six-row list; other
row counts, grid layouts and very long filename presentation are not certified
by the screenshots above.

## Shared font replacement

The next validation image installs Noto Sans JP Regular 2.001 as the shared
`skins/font.ttf` in the initial files and the active 350teric home. SDL_ttf
opens the original OpenType bytes through Esoteric's expected filename. Both
copies include the [SIL OFL 1.1 notice](../../assets/frontend/licenses/NotoSansJP-OFL.txt).

Before generating the image, the RG350M rendered Amber at 320×240 using the
existing 350teric executable and a temporary home. The original and replacement
were compared on the emulator list, settings and ROM selector. The replacement
showed all five visible Japanese names, including 忍者龍剣伝 and 星のカービィ 夢の泉の物語.
The frame, six rows and orange selection stayed in place. Moving the selection
and returning to the emulator list worked. The device was then returned to the
plumOS frontend.
