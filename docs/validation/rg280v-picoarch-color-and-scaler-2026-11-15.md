# RG280V PicoArch 描画色と拡大処理の調査（2026-11-15）

## 条件

- RG280V実機、CPU上限996 MHz、SD2のROM、ADBによる時間制限付き起動。
- DRM画面をPNGで取得し、SDL更新FPSとPCM信号を記録した。画像とROM本体はGitに含めない。
- 単体FCEUXのSuper Mario Bros.画面を色の参照にした。

## 原因と対処

FCEUmmが出したXRGB8888画素 `0x5d96ff` はNESの空の青であり、PicoArchがRGB565へ変換した値 `0x5cbf` も正しい。しかし変更前のDRM取得画像は `(189, 234, 230)` だった。SDLへ渡す16ビット画素のバイト順が、この変換経路では実画面の順序と逆だった。画面反転直前にXRGB8888由来の画素だけバイト順を入れ替えた結果、空の色はFCEUXと同じ `(90, 149, 255)` になった。

PICO-8/fake08のRGB565経路は変更前の色が正常だった。全コアの画素を入れ替える試験では、黒い背景が黄緑に崩れたため、その案は採用していない。QuickNESは画素順を変えてもFCEUXとパレットが一致せず、代替のNESコアとして色の再調査が必要。

拡大処理は行単位の最近傍処理へ変更した。既定の走査線効果を外し、文字向け最適化を無効にした。これは色修正とは別の変更であり、低FPS対策である。

| コア・同一条件の比較 | 変更前 | 今回 | 色の結果 |
| --- | ---: | ---: | --- |
| FCEUmm / Baseball | 19.8 FPS | 58.8 FPS | 枠色のバイト順を修正 |
| Nestopia / Baseball | 19.8 FPS | 59.8 FPS | 枠色のバイト順を修正 |
| fake08 / Celeste | 23.7 FPS | 23.7 FPS | 従来の色を保持 |
| Genesis Plus GX / 同一ROM | 約51.5 FPS | 51.9 FPS（全画素入替え試験） | 現行版ではRGB565経路を保持 |
| Snes9x 2010 / 同一ROM | 19.5 FPS | 45.0 FPS（全画素入替え試験） | 画面が黒く、未解決 |

NESの約59 FPSはゲーム速度や音質の実機目視・聴覚確認を代替しない。PICO-8の23.7 FPS、Snes9x 2010の黒画面、QuickNESのパレット差、ほかのコアの色は未解決。PicoArchメニュー内の色とFEからの通常起動・終了も改めて確認する。

再生成元は `scripts/patch-rg280v-picoarch.py`。今回の実機配置バイナリのSHA-256は `2fdb82614f6f02de58066c41aa57faa2248d8da3cd02f3aec30bdfa139012665`。配置後のSD側ハッシュも一致し、試験後にFEのプロセスと996 MHzを確認した。
