## FBA44 dynamic-library clause

- Barry Harris's December 2011 initial Git import already contained the DLL clause. Its Windows code directly loads `kernel32.dll` to attach a console, a use unrelated to network play. The reviewed public history does not identify when or why the clause was first written. [Initial license](https://github.com/barry65536/FBAlpha/blob/e4cc7bbf303177aa165c181a17efcdf422829959/src/license.txt#L1-L9) · [Windows console code](https://github.com/barry65536/FBAlpha/blob/e4cc7bbf303177aa165c181a17efcdf422829959/src/burner/win32/main.cpp#L344-L357)
- In FB Neo PR #26, barbudreadmon noted that a literal reading would also cover DirectX. Dink and tmaul discussed the unclear original intent, and tmaul agreed to removal given the emulator's dependency on DLLs. Dink merged the deletion on May 22, 2019. The change applies to FB Neo's text. The FBA44 revisions used by nobk and plumOS retain the clause verbatim and provide no express Linux exception. [Development discussion](https://github.com/finalburnneo/FBNeo/pull/26) · [Removal commit](https://github.com/finalburnneo/FBNeo/commit/de4cc9e9bbf0aa472231d2e4986d5498e649a241) · [nobk license](https://github.com/nobk/fba-sdl/blob/9360dcc4b42f3e74e0b683fbd1abc37ee14f09e8/src/license.txt#L1-L9)
- The locally retained Fix 06 OPK matched the author's downloadable release by SHA-256. Its `fbasdl.dge` requires SDL 1.2, SDL_image, zlib, libpng and libao as shared libraries. The modified executable in the font-validation IMG has the same SDL, SDL_image, zlib and libpng dependencies and uses ALSA in place of libao. The additional `fbasdl_lepus.dge` in that OPK matches the author's version and also uses shared SDL and libao. These builds demonstrate the port's use of shared libraries for normal frontend and audio functions. The public materials reviewed do not confirm that FBA44 permits this configuration in a redistributed OS image. [Author's OpenDingux release](https://github.com/plrguez/fba-sdl/releases/tag/r19_2021-10-18-.44_od_beta-fix-06) · [Build flags](https://github.com/plrguez/fba-sdl/blob/9448a9c6f1040ad8ec204b5e9cb83e25574ac0c8/Makefile.dingux#L108-L115)
- The readback of the font-validation IMG found the verbatim FBA44 notice in neither the FBA44 OPK nor the shared licenses directory. It remains available in the source supplement and in [the project tree](../../assets/frontend/licenses/FBA44-LICENSE.txt). Ensure the exact license text accompanies any release, with corresponding source and build inputs, component notices, the non-commercial and donation conditions, the three-year rule and no unauthorized ROMs. Clarification that covers the standalone Linux port and the listed shared dependencies remains open.

### Static-link trial on RG350M

A separate OPK uses the existing FBA44 MIPS soft-float build objects and statically links SDL 1.2, SDL_image, ALSA, libdrm, libudev, libiconv, libpng, zlib and the compiler runtime. The SDL build disables its dynamic loading API and ALSA shared backend. The ALSA build disables runtime plugin loading. The final MIPS ELF has no dynamic section, `DT_NEEDED` entries or interpreter segment. The trial package retains the existing GCW0 launcher and skins, includes the verbatim FBA44 license, and contains one executable. The older Lepus executable and its entries are outside the four-device trial package.

On RG350M, ADB launched the package through `opkrun` using temporary storage. A file-open trace of the FBA44 executable during Kung-Fu Master showed DRM and ALSA device access and no shared-library opens. SELECT+START opened the menu, B resumed the game, and Exit returned status 0. The plumOS frontend was started again. The installed OPK and saved IMG still match their recorded SHA-256 values.
