# RG280V PCSX4ALL: Tobal 2の解像度・入力確認（2026-11-16）

追記：RG280Vには物理アナログスティックがないため、PCSX4ALLの起動時・設定初期化時の既定値と既存SD1の共通設定をDigital（`Analog_Mode 0`）へ変更した。以下の共通設定がアナログモード3だった記述は比較試験時点の状態を指す。

対象はSD2の `Tobal 2 (Japan) (v1.1).cue`。BINは669,555,600バイトのMODE2/2352で、元ファイルにCUEがなかったため単一データトラックのCUEを作成した。PCSX4ALLのMIPS再コンパイラとGPU Unaiを使用。測定時のCPU周波数は996 MHz。

画面上部の表示はPCSX4ALLの性能モニターで、`512x480x15` はゲームが指定した内部映像モード、`CPU` はPCSX4ALLプロセスのCPU使用率、`FPS` は実測フレーム数とNTSC目標値の60を表す。DRM画面はADBで取得した。1枚のFPS表示は約1秒間の値であり、長時間平均ではない。

| 設定 | DRMバッファ | 対戦中に取得した表示 | 結果 |
| --- | --- | --- | --- |
| Hardware scaling、画素間引きなし | 512×448 | 43〜49/60 FPS、CPU 98〜100% | 基準。 |
| Software scaling、画素間引きなし | 320×240 | 42〜50/60 FPS、CPU 99〜100% | 出力解像度は下がるが、明確な速度改善なし。 |
| Software scaling、画素間引きあり | 320×240 | 47〜50/60 FPS、CPU 99〜100% | 高解像度の横方向を間引いても60 FPSに届かない。 |

画素間引きはPCSX4ALLソースの `PixelSkipEnabled()` によりsoftware scaling時だけ有効になる。Tobal 2専用のSD1設定ファイルで `VideoScaling 1` と `pixel_skip 1` を指定し、ほかのPSXゲームの共通設定は `VideoScaling 0` に戻した。画面の小型化だけではゲーム内部の512×480モードは変更されない。性能モニターがCPUほぼ100%を示すため、今回の条件では描画出力サイズだけが主な制約とは考えにくい。

入力は最初 `Analog_Mode 3`（DualShockのアナログモード）で、画面右上にも `A` と表示されていた。RG280Vには物理アナログスティックがない。十字キーをPCSX4ALLはデジタル方向キーとして渡しているが、Tobal 2の対戦中の移動には効かず、ゲーム内メニューでは効くとのユーザー報告。ユーザーが `Analog Mode` を `Digital` に切り替えると対戦中の十字キー操作ができた。

終了後、Tobal 2専用設定に `Analog_Mode 0` が保存されていることを確認した。速度の改善が明確でなかったので、Tobal 2専用設定の `VideoScaling 0` と `pixel_skip 0` を復元し、`Analog_Mode 0` だけを残した。共通PSX設定は `Analog_Mode 3`、`VideoScaling 0` のまま。最終のTobal 2専用設定ファイルはSHA-256 `6996ad22092018ba19e98c639c2e4cb230928003e4ac53f0c748497709ac844d` で端末上の一時ファイルと照合して配置した。画素間引き有効時の音と画質のユーザー評価、最終設定での再起動後操作は未確認。
