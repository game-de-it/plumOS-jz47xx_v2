## Actual FE round trip

From the running native FE, NES → Akumajou Densetsu was launched using a temporary
ROM-level QuickNES selection. SELECT+START opened the emulator menu; its Exit
returned to the same FE PID 1341 and the NES ROM screen. This was a genuine
launcher/return test, separate from restarting the FE service after direct
dispatcher probes. The original core-overrides JSON was restored byte-for-byte
afterward (both hashes `720963306e4e332eb4ed4c94056cf5be1754112dbce01c771c5fbc353b8be547`).

At the end ReGBA was closed through its menu. FE PID 1510 and a clean TOP screen
were confirmed; no tested emulator process remained.

## Probe and procedure corrections

- The cloned per-system cache retained older alias spellings. The full index
  scan alone does not refresh every `state/frontend/systems/ID.json`. GB/GBA
  were refreshed individually and paths were taken from the actual cache,
  rather than treating a cache miss as an emulator failure. Ordinary FE ROM-list
  entry already performs the corresponding scan.
- The legacy standalone probe produced invalid floating-point printf fields
  when used with ReGBA. Its report formatting now passes only integer arguments
  to printf while preserving decimal log fields. Rebuilt MIPS probe logs gave
  plausible 59.750 FPS / 60.008 FPS windows and consistent audio counts. The
  new probe lived in `/tmp`, not in a global emulator preload configuration.
- Some OPK payloads escape the watchdog launch process group. A watchdog
  timeout therefore cannot prove all apps have exited. FCEUX 2.6.6 remained as
  `fceux_gcw0` PID 1107; its executable was checked, then that specific test
  process was terminated and the unused OPK mount released. Goodboy startup
  failures and attempted FE captures while that process remained were discarded.
  The clean Goodboy retry succeeded. Future automation must check payload PIDs
  and prefer the normal emulator Exit path; the old watchdog alone is insufficient.
- FCEUX 2.2.3's inherited Mario settings contained invalid scale values.
  Trying sane scales and removing the ROM override did not fix startup. Both
  test changes were reverted; the original file remains backed up and restored.
  A second ROM reproduced the failure. The subsequent clean-HOME diagnosis and
  actual correction are recorded in `rg300x-fceux223-mode-check-2026-11-19.md`.

Private generated evidence, telemetry, launch logs and screenshots are under
`output/rg300x-validation/`. No private ROMs, BIOS or binary captures enter Git.
The development ADB server for this session was port 5043; stock adbd product
strings were not used as device identity.
