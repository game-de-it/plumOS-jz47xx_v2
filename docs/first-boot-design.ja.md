# JZ47xx版の初回セットアップ設計

## 現状と参照元

設計開始時点のRG280V版には初回セットアップがなかった。旧3領域試験イメージは
p1 FAT 512MiB、p2 ext4 1GiB、p3 FAT 512MiBを生成済みで、カードの残りを
使わなかった。既存の2領域SDも起動する。

V90Sの `scripts/assemble-v90s-four-partition-image.sh` はp1からp3までの
seedを作り、ユーザー用p4を作らない。`scripts/v90s-four-partition-init` は
ルート切替前に以下を実行する。

1. 起動元、ラベル、各領域の開始位置・長さ、カードの最小容量を確認する。
2. 管理用p3を目標容量へ拡張し、`e2fsck` と `resize2fs` を実行する。
3. 残りにユーザー用p4を新設し、**新設した場合にだけ**FAT32で初期化する。
4. ROM・BIOSなどのディレクトリを作り、途中経過と完了印を永続領域へ記録する。
5. Systemイメージのハッシュを検証し、各領域を引き継いでルートへ切り替える。
   次回起動では完了印と整合性を確認し、失敗時は復旧経路へ入る。

## JZ47xx版で守る条件

- UBIBootとOpenDingux Linux 6.8、mininitは起動基盤として使う。V90Sの
  GPT、AArch64実行ファイル、Linux 4.9、容量値はコピーしない。
- 起動元SDは `/boot` のデバイスから特定する。SD2や別のカードを誤って
  初期化しない。MBR上のp1/p2位置とラベルを検査してから変更する。
- 新規配布seedはp1 FATとp2 ext4まで。p3は初回起動で**未割当領域に限って**
  作る。p3が既に存在する場合はFAT32と `PLUMOS` ラベルを検証し、
  不明な形式やラベルなら停止してログを残す。既存p3を自動初期化しない。
- p2にはアプリ・設定・作業記録、p3には利用者ファイルを置く。p3を
  カード末尾まで確保し、カードの公称容量差を吸収する。p2の将来容量は
  アプリ層の容量検証を踏まえて決める。
- 領域表の変更後にカーネルが新p3を認識できなければ安全に再起動し、
  次回にフォーマット・ディレクトリ作成を再開する。進捗をp2へ段階別に記録し、
  書き込み後に `sync` する。完了印はp3が再マウントできてから最後に書く。
- セットアップ中は画面に大きな進捗と失敗理由を表示し、同じ内容をp1 FATと
  p2 ext4に記録する。失敗時は診断シェル/ADBを残し、通常の起動扱いにしない。
- 既存の2領域**開発用SD**は無断で変更せず、明示的な移行操作まで従来通り
  起動させる。新規seedと区別する印をp2へ置く。

## 実装順序と検証

1. seed形式と起動元・領域表の検査を実装し、既存SDと新seedを判別する。
2. 未割当領域へのp3作成、再起動を挟む中断再開、FAT初期化、ディレクトリ作成を実装する。
3. 小容量・不正ラベル・途中停止・再起動・再実行をイメージで検証する。
4. RG280V実機で新規SDの初回起動と2回目起動、ADB、p3全容量、SD2を確認する。

## 実装状況

新しい `plumos-rg280v-firstboot-seed.img` はp1/p2だけを持ち、p2に
`seed-v1` 印を格納する。`plumos-first-boot` は起動元の位置・ラベル・容量を
確認し、未割当領域にp3を作って再起動する。次回は作成意図の印とp3の位置・
容量を確認し、未フォーマットの場合にだけFAT32を作る。ディレクトリと
`.plumos-ready`、p2の完了印を最後に書く。失敗時は画面・ログ・ADBを残す。
固定512MiB p3の旧イメージは初回セットアップ対応版ではない。

この実装の**実機初回起動、再起動を挟む再開、画面表示、全容量利用は未検証**。
System A/B更新や4機種共通の機種判別は別工程とする。
